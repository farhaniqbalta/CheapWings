## Scope and architecture

Owner selected Fli after a preliminary Viajante evaluation and explicitly
approved **C3/1s**. Viajante remains an isolated experiment, not a production
dependency/provider. Fli is a fourth selectable source alongside Skiplagged,
swoop and OctoTrip. It does not replace them or establish independent inventory
confirmation: Fli and swoop both query Google Flights, explained in the form
and quote warnings. P4.10's location catalog and scope controls are preserved.

Reused the existing SQLite queue, global admission ceiling **9**, independent
provider start pacing/concurrency, fair claims, leases/fencing, retries,
cancellation, shared in-flight operations, immutable observation cache and
progressive result commits. No new scheduler, service, database or migration.
`FLI_CONCURRENCY=3`, `FLI_INTERVAL_SECONDS=1` are configurable like other sources.
Fake/live mixing and accepted personal-use scope rules remain enforced.

Fli source 0.10.0 is pinned to commit
`881aee5ff4321e81ea2157cb44be94ce6a21dc1b`; PyPI's 0.9.0 was not substituted.
Pinned curl-cffi 0.17.0. Dependency installation therefore needs Git. Normal
backend/dev setup stays usable without optional live packages: Fli is disabled
with an install reason when absent, and SDK-specific tests skip appropriately.

## Adapter and correctness

- Uses pinned Fli public-page protobuf builders and row decoder. One synchronous
  native HTTP request path runs in the existing bounded executor; it has no
  hidden SDK worker pool. The durable runner owns retries, and logical timeout
  or cancellation does not free physical capacity while native I/O continues.
- Explicit HTTP/2 (`CurlHttpVersion.V2TLS`) follows observed TLS connection
  failures. Uses the SDK's normal Chrome transport profile; no identity/proxy
  rotation, fabricated protection token, consent-cookie fabrication or challenge
  handling. Only normal same-host flight-page redirects are allowed. Traffic
  checks/consent/unsupported redirects stop unsent peers; 429 honors Retry-After
  seconds/date with the existing conservative 120s fallback and durable cooldown.
- Parses original public-page JSON numeric lexemes as Decimal. The SDK decoder
  receives a constant price placeholder solely for identity/currency decoding;
  actual money never enters its float price model. Positive exact source prices,
  currency, endpoint airports, date, clocks/timezones and segment identity are
  validated before commit. Links are allowlisted Google query pages, labeled as
  generic search links. Opaque booking tokens/handles are not persisted.
- Missing ds:1, error/unrecognized structures and all-null payloads fail explicitly;
  they cannot become swoop-style false-empty success. True recognized empty lists
  remain valid source responses, but unpriced/empty observations are incomplete
  for caching. Complete priced observations reuse the existing cache without
  renewing source age/retention. Payload/row bounds prevent unbounded decoding.
- Offers are indicative, unknown baggage/fees/hidden-city/self-transfer risk;
  no exact repricing is advertised. Basic-economy exclusion is rejected before
  dispatch, not silently ignored. Unknown SDK airport codes report unsupported.
  **Lowest advertised** displays these quotes; **Best checked deal** continues
  excluding quotes without the required comparable-total/risk evidence.
- Checked-bag allowance is not reliably exposed by this Fli path and remains
  unknown. Quotes are not confirmed seller fares or bag-inclusive totals.

## Controlled live observations

Standalone SDK first returned 10 priced HND→CGK/November 20/IDR options in
**1.057s**, proving current Fli can retrieve data here. Initial adapter native
transport was intermittent: one call failed before HTTP, another returned 10
normalized offers in **9.700s**. The initial no-retry durable trial persisted
11 offers from one of three searches; a normal retry-budget diagnostic then
recorded nine libcurl **35 (TLS connection)** failures and zero successful
queries. Those failures must not be called empty inventory or HTTP throttling.

The final explicit-HTTP/2 configuration was tested twice with the same three
route/dates: HND→CGK, November 20–22, 2026, one adult/economy, IDR. Disposable
migrated SQLite databases; actual Fli adapter and runner; no application cache,
repricing or automatic retries in the final two trials. Source protections and
existing live-job/cooldown guard were retained.

Final repeats' first persisted result: **1.470 / 0.962s**. Fetch latency
p50/p95: **0.995/1.333s**, then **0.835/0.878s** (N=3; p95 is the maximum).
Measured start gaps: **1.0105/1.0278s**, then **1.0112/1.0050s**. No 429/blocking
response in these trials. No requests overlapped within a provider beyond C3;
final live peak was 2 because responses were fast, while native failure controls
and offline tests reached 3. Configuring C3 is not proof of three-way successful
live overlap or of optimal/sustained safe throughput. No interval was shortened
to manufacture overlap. Six successful searches across two small repeats give
preliminary confidence only; time-varying network/provider conditions remain a
confounder to attributing all improvement solely to HTTP/2.
