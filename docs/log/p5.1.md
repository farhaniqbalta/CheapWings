## Behaviour changes

- **Setup:** the backend now needs a Rust toolchain and
  `.venv/bin/maturin develop --release -m core/cheapwings-py/Cargo.toml` (README updated;
  `maturin` added to `backend[dev]`). Importing `cheapwings.domain.money` without the module
  fails with that command in the message.
- **Precision:** amounts are exact up to Rust's 96-bit decimal mantissa (~7.9×10²⁸,
  about 28.9 digits), including values Python's 28-digit context used to round
  (`test_beyond_28_digits_is_exact`). Anything larger now raises `ValueError` instead of
  being rounded silently (`test_beyond_96_bit_raises_instead_of_rounding`), e.g. a 30-digit
  JPY `as_minor_units()` (old: `…567900`) or `Money.from_minor_units(10**30, "USD")` (old:
  `1.000…E+28`). Integers beyond 128 bits also raise `ValueError`.
- **Non-finite amounts:** FX on a NaN amount raises `ValueError` (old: returned NaN);
  `as_minor_units()` on Infinity raises `ValueError` (old: `OverflowError`).
- **Not identical in extreme edge cases** (deferred, unrealistic for fares): when amount × rate
  needs more than 28 decimal places, Rust rounds the product before the half-even step
  (`1.000000000000000000000000001 × 0.005` → USD `0.00`, old `0.01`); a literal `-0` amount
  converts to `0.00` (old `-0.00`).
- **Fixture generator:** money answers come from a pure-`Decimal` reference inside
  `scripts/gen_core_fixtures.py`, not from `cheapwings.domain.money` (which now calls Rust),
  so regenerating cannot make the gate test Rust against itself
  (`test_generator_money_reference_runs_without_rust_core`).

## Rulings made during implementation

- Workspace members added as each crate appeared (Cargo rejects missing members).
- `serde` is a normal dependency of the core (core structs derive `Deserialize`).
- The Rust Fli decoder does not validate airport/airline codes against fli's tables (Python's
  `parse_flight_row` fails `schema_changed` on unknown airports); `cross_check` still rejects
  query mismatches. Add a code table if this matters.
- PyO3 crate imports the core as `engine` (name clash with the module function).
- `test_core_module_is_rust` checks for a native built-in (maturin installs a package whose
  `__init__.py` re-exports the `.so`).
- Swift errors: `CoreError.Invalid(message)`, `FliDecodeError.Failed(code, detail)`.
