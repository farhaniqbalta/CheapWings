## Behaviour and limits

- Strictly one Fli request at a time, ≥1 s apart; any 429, block page or off-path redirect
  stops the search, keeps found offers and shows why. No retries.
- Fli prices shown as **indicative** ("fees & bags unknown") and ordered by the core's
  lowest-advertised view.
- Foreground-first: the screen stays awake while searching; on backgrounding the in-flight
  request finishes and the search stops ("paused"); there is no resume yet.

## Rulings made during implementation

- 66 planning fixture cases (60 random + 6 fixed) vs the plan's "60 + errors".
- `FoundOffer` is built from route/date + row index, which forms its `id`.
- A decoded page with no priced rows emits no `.offers` batch (progress only).
- Background pause = stop at the next progress event under `beginBackgroundTask`.
- The SwiftUI layer has no automated tests (plan: build + owner device run).

## Final review (fresh subagent, Opus)

0 Critical, 4 Important, 8 Minor. Fixed in one pass (tests first where testable):
- **401/403 now stop the search** like `providers/fli.py` `_deny()` (plan amended); before,
  the engine kept sending requests to a server already refusing it.
- **Empty results are classified**: "No flights found", "page format may have changed"
  (only when every failure is a decode failure) and "N searches failed" (e.g. offline), with
  the skipped list always visible. Search state moved into `CheapWingsKit.SearchSession`.
- **Starting a search cancels any still-running one**, and a generation token drops late
  events, so two engines can never run (pacing holds).
- **Compact width** (iPhone, iPad Split View): results column shown when a search starts
  (build-verified only — a simulator tap would send live requests).
- **Background task**: expiration ends synchronously on the main thread; never two at once.

Deferred minors: one more request can start if the app backgrounds during the 1 s wait;
the 8 MB cap is checked after download; `980.5` is not padded to `980.50`; `plan_search`
builds pairs before checking the cap, and impossible-date/year-0 paths are untested.
