## Owner-found crash and the continued-processing decision

- **First device build crashed on Search** (SIGABRT): iOS asserts in
  `-[BGTaskScheduler _handleSubmissionWithoutRegistrationForTaskRequest:]` when a
  `BGContinuedProcessingTaskRequest` is submitted without a registered handler (crash log pulled
  with `devicectl`).
- **Diagnosis on the device (console launch):** `register(forTaskWithIdentifier:
  "dev.cheapwings.app.search.*")` returns `false` — also when moved to the app delegate's
  `didFinishLaunching`, and also with `UIBackgroundModes: processing` (reverted). The built
  `Info.plist` does list the identifier. Cause not identified; free Personal Team signing is a
  suspect, unconfirmed.
- **Fix:** registration in the app delegate; `submit` refuses unless registration succeeded, so
  the assertion cannot recur. On this device searches stay **foreground-first + resume**.
- **Ruling (deferred):** iOS 26 continued processing is an open item, not working on the owner's
  device. Next step if wanted: test with a paid developer team or on another device, or file
  feedback with Apple.

## Rulings made during implementation

- `rusqlite` pinned at the current 0.42.0 (plan named an older version "to verify").
- `Serialize` added to core `FliLeg`/`FliOffer` for JSON storage of legs.
- Checkpoint on the engine's per-route/date `.progress` instead of new `IndexedRouteDate` /
  `.comboFinished` events (same guarantee, engine API unchanged).
- `SearchPersistence` protocol so a failing store can be tested.
- A second Resume tap while resuming is ignored (never two engines).
- `StopReason.interrupted` for a search found unfinished with no stored stop reason.
- Hidden-offer reasons stored per route/date (summed on read) to keep re-finish idempotent.

## Final review (fresh subagent, Opus)

0 Critical, 3 Important, 7 Minor. Fixed in one pass:
- **Resume without working history** (store failed to open or a write failed) was a dead
  button; it now resumes the unfinished route/dates from memory (2 tests RED → GREEN).
- **Resume after the 30-minute cooldown** now enables itself when the time passes
  (`TimelineView` redraw; build-verified).
- **README** no longer claims background searching on iOS 26; it states the feature is off.

Deferred minors: continued-processing code paths to harden before enabling it (progress
updates from the model, a second task replacing the first, pause vs attach race);
`storeError` never cleared and shown in raw form; no schema-migration hook and no recovery
from a corrupt file; offers briefly on screen before their route/date is saved (re-run on
resume, plan-accepted); a failed stop write loses the post-block cooldown; test gaps (NULL stop
reason restore, prune cascade of child rows, a 429 stop); failed route/dates are not retried.
Reviewer-declined, noted for a future ruling: a brand-new search right after a block is not
covered by the cooldown (the plan gates only Resume).
