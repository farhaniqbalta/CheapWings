# Fli 0.25 s interval reliability (owner request, 2026-11-14)

Owner goal: if Fli is reliable at a 0.25 s start interval, use it for both web and the iPad.
P4.12 had only single 12-request batches (no block at ≤4 req/s, "not evidence of sustained
safety"). This run tests a full app-sized search, twice.

Setup: `scripts/benchmarks/p411_fli_live.py` (real durable JobRunner, production Fli
provider and thread pool, disposable DB, no cache, no retries, stops on the first 429 or
traffic check). HND→CGK, one search per date from 2026-12-01, G16, from the owner's Mac
(home IP), web server idle (read-only live guard passed). Runs one at a time.
Raw results: `scripts/benchmarks/artifacts/p55_fli_quarter_second.jsonl`.

| Run | Interval | Searches | Succeeded | Offers | Errors / blocks | Batch s | Searches/min | Latency p50 / p95 / max s | Peak in flight |
|---|---|---|---|---|---|---|---|---|---|
| A1 baseline | 1.0 s | 30 | 30 | 325 | 0 / 0 | 30.3 | 59 | 0.93 / – / 1.12 | 2 |
| A2 | 0.25 s | 120 | 120 | 1,367 | 0 / 0 | 32.1 | 224 | 0.88 / 1.14 / 1.35 | 5 |
| A3 (+2 min) | 0.25 s | 120 | 120 | 1,367 | 0 / 0 | 32.1 | 224 | 0.75 / 0.98 / 1.18 | 5 |

270 live requests in about 5 minutes: no failures, no 429, no `/sorry` redirect, latency not
rising. A full 120-search Fli job takes about 32 s at 0.25 s against about 2 min at 1 s.

Limits: one route, one IP, one session; it shows no block at a full search twice in a row,
not safety over days of use or from other networks. Keep the existing stop-on-429/block and
30-minute cooldown.

## What 0.25 s means on each client

- **Web** (`FLI_INTERVAL_SECONDS`): start-to-start pacing with requests in parallel, so 0.25 s
  gives the 4× speed-up measured here.
- **iPad** (`SearchEngine(interval:)`): strictly sequential, the interval is a wait *after*
  each reply, so 0.25 s gives about 1.1 s per search instead of about 1.9 s (≈1.7×), not 4×.
  The 4× needs start-to-start pacing with up to ~5 requests in flight on the iPad (engine
  change, not yet made). The iPad's URLSession traffic was not part of this run.
