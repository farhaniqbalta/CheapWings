# P5.5 iPad Feature Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the iPad search to parity with the web app for Fli searches: pick airports by typing (airports, cities, countries) with "Major airports" for curated cities/countries, a max-stops filter, and itinerary details (flight numbers, stops, total duration, layovers, airport changes, leg list).

**Architecture:** The shared location catalog (`backend/src/cheapwings/locations/catalog.json`, identical to `apps/web/public/locations.json`) is bundled into the app unchanged and parsed by a new Rust `locations` module (search, browse airports of a place, authoritative Major resolution, airport lookup) — a port of `locations/catalog.py`, exposed via UniFFI. Stops filtering and airport-change detection join the Rust `fli` module. Swift computes durations with the OS time-zone database from catalog time zones; SwiftUI adds the picker, filter and detail screens.

**Tech Stack:** Rust (`cheapwings-core`, UniFFI 0.32.2), Swift (CheapWingsKit, SwiftUI), XCTest, XcodeGen.

**Spec:** [P4.10 smart locations](p4.10.md) (catalog semantics: typed search, browse-never-auto-selects, Major resolution with version check, no metro-only codes), `backend/src/cheapwings/locations/catalog.py` and `api/contracts.py` (`to_domain` major rules), web `apps/web/src/components/{SearchForm,AirportMultiSelect,ItineraryCard}.tsx`, [P5.06 owner decision](p5.06.md#owner-decision-2026-11-13-after-s5) (Rust owns shared logic), [P5.3](p5.3.md).

## Global Constraints

- One catalog file, no copy: the app bundles `backend/src/cheapwings/locations/catalog.json` as a resource at build time (XcodeGen path reference); Rust parses it at launch. Catalog validation mirrors `LocationCatalog.__init__` (unique IDs/codes, associations, major mappings) and fails closed.
- Search semantics = `LocationCatalog.search`: Unicode-folded (NFKD, casefold, combining marks dropped) substring over name, code, city, country name, aliases; ≤ 100 characters; order (exact code, exact name/alias, type, folded name, id); `within` a location lists only its airports; the empty term with `within` lists them all; browsing a place never selects it.
- Major resolution = `LocationCatalog.resolve`: version must match; type must match; only curated `major` mappings; codes sorted; rationale + definition returned; metro-only codes are never searchable airports.
- Max stops: Any / Nonstop / ≤ 1 / ≤ 2, applied per offer in Rust (`legs − 1 ≤ max`), dropped offers counted as hidden with reason `stops N > max`; the Fli request itself is unchanged (`providers/fli.py` also requests any stops).
- Stored requests stay readable: new request fields are optional with serde defaults, so P5.3 databases resume without migration.
- Durations from naive local leg times + airport IANA time zones (catalog) via `TimeZone`; if a zone is missing the duration is omitted, never guessed.
- Airline names are not available from Fli; show codes (web falls back to codes too).
- No live provider requests by the implementer; device check by the owner. PR left for owner review.

## Review Focus

1. Typing a city with no curated Major list must not offer "Major airports" (Specific only), and a stale catalog version must not silently resolve — Task 1.
2. Picking a country's Major airports must search exactly the curated codes (and show which), never all airports of the country — Task 1 + Task 2.
3. A connection that changes airports (e.g. NRT → HND) must be flagged, not shown as a normal layover — Task 1 + Task 3.
4. Overnight legs and time-zone changes must give correct total and layover durations (CGK UTC+7 → HND UTC+9) — Task 2.
5. Resuming a search stored by P5.3 (no stops/selection fields) must still work — Task 2.
