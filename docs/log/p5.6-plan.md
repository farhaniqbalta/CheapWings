# P5.6 iPad Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the iPad app dependable and comfortable in everyday use: honest offline behaviour (pause, then Resume), a fast and correct airport picker, and accessibility (VoiceOver, larger text, dark mode) plus narrow windows (Slide Over / iPhone) working.

**Architecture:** Offline detection lives in the Swift engine (`URLError` codes that mean "no network" stop the search as a new `StopReason.offline`, so the unfinished route/dates stay pending for P5.3 Resume) and in the app (`NWPathMonitor` drives the form and the Resume button). Picker fixes go into the Rust `locations` module (result limit + total, Python-exact mark folding) and its FFI. Accessibility and layout are SwiftUI-only changes, checked with simulator screenshots and the owner's device.

**Tech Stack:** Rust (`cheapwings-core`, UniFFI 0.32.2), Swift (CheapWingsKit, SwiftUI, Network framework), XCTest, XcodeGen, `xcrun simctl` screenshots.

**Spec:** [P5.5 final-review deferred minors](p5.5.md#final-review-fresh-subagent-opus), [P5.3 resume](p5.3.md), [05 → Native iOS](../05_WEB_AND_NATIVE_IOS.md) (Dynamic Type, VoiceOver, dark mode, offline/error states, iPhone and iPad layouts), [01 → accessibility](../01_PRODUCT_REQUIREMENTS_UX.md) (VoiceOver labels, 44 pt targets, Dynamic Type), owner order 2026-11-14 (iPad Fli-only; parallel pacing after P5.6; [02 Discover seams](../02_SYSTEM_ARCHITECTURE.md#keeping-current-work-ready-for-discover-owner-2026-11-14)).

## Global Constraints

- Fli interval stays 0.25 s, engine stays sequential (parallel pacing is the next step, not this one).
- Offline is a pause, not a failure: route/dates not finished because the device is offline are never stored as failed; the search stops with `offline` and Resume continues them. Other network errors (timeouts, TLS) keep today's per-route/date `network` failure.
- `URLError` codes treated as offline: `.notConnectedToInternet`, `.networkConnectionLost`, `.dataNotAllowed`, `.internationalRoamingOff`.
- Picker search: Rust returns at most `limit` locations plus the total match count; order unchanged; folding drops only marks with canonical combining class ≠ 0 (Python `unicodedata.combining`), keeping the ß→ss rule.
- Over-long query (> 100 characters) shows the catalog's error text, not "no matches".
- Durations never negative: inconsistent leg times give "unknown", never "-1h".
- No new colours or fixed font sizes; system colours and text styles only; every interactive control ≥ 44 pt and labelled for VoiceOver.
- Keep Discover seams (02): no Search-form-specific logic added to the Rust core.
- No live provider requests by the implementer (simulator screenshots stop before Search); device checks by the owner. PR left for owner review.

## Review Focus

1. Wi-Fi off mid-search: the search pauses within one request, unfinished route/dates are not marked failed, and Resume finishes them once online — Task 1.
2. Starting a search while offline is blocked with a clear message, and Resume stays disabled until the connection returns — Task 1.
3. Typing one letter ("a") in the picker stays responsive and still says how many more matches exist — Task 2.
4. VoiceOver can reach "Add major airports" as its own button, and a flight row reads price, stops, duration and warnings in one swipe — Task 3.
5. At the largest accessibility text size, flight rows and the detail screen do not truncate prices or overlap — Task 3.
