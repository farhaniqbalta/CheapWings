# P5.6 iPad Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the iPad app dependable and comfortable in everyday use: honest offline behaviour (pause, then Resume), a fast and correct airport picker, and accessibility (VoiceOver, larger text, dark mode) plus narrow windows (Slide Over / iPhone) working.

**Architecture:** Offline detection lives in the Swift engine (`URLError` codes that mean "no network" stop the search as a new `StopReason.offline`, so the unfinished route/dates stay pending for P5.3 Resume) and in the app (`NWPathMonitor` drives the form and the Resume button). Picker fixes go into the Rust `locations` module (result limit + total, Python-exact mark folding) and its FFI. Accessibility and layout are SwiftUI-only changes, checked with simulator screenshots and the owner's device.

**Tech Stack:** Rust (`cheapwings-core`, UniFFI 0.32.2), Swift (CheapWingsKit, SwiftUI, Network framework), XCTest, XcodeGen, `xcrun simctl` screenshots.

**Spec:** [P5.5 final-review deferred minors](p5.5.md#final-review-fresh-subagent-opus), [P5.3 resume](p5.3.md), [05 → Native iOS](../05_WEB_AND_NATIVE_IOS.md) (Dynamic Type, VoiceOver, dark mode, offline/error states, iPhone and iPad layouts), [01 → accessibility](../01_PRODUCT_REQUIREMENTS_UX.md) (VoiceOver labels, 44 pt targets, Dynamic Type), owner order 2026-11-14 (iPad Fli-only; parallel pacing after P5.6; [02 Discover seams](../02_SYSTEM_ARCHITECTURE.md#keeping-current-work-ready-for-discover-owner-2026-11-14)).

## Global Constraints

- Fli interval stays 0.25 s, engine stays sequential (parallel pacing is the next step, not this one).
- Offline is a pause, not a failure: route/dates not finished because the device is offline are never stored as failed; the search stops with `offline` and Resume continues them. Other network errors (timeouts, TLS) keep today's per-route/date `network` failure.
- `URLError` codes treated as offline: `.notConnectedToInternet`, `.networkConnectionLost`, `.dataNotAllowed`, `.internationalRoamingOff`.
- Picker search: Rust returns at most `limit` locations plus the total match count; order unchanged; folding drops only marks with canonical combining class ≠ 0 (Python `unicodedata.combining`), keeping the ß→ss rule.
- Over-long query (> 100 characters) shows the catalog's error text, not "no matches".
- Durations never negative: inconsistent leg times give "unknown", never "-1h".
- No new colours or fixed font sizes; system colours and text styles only; every interactive control ≥ 44 pt and labelled for VoiceOver.
- Keep Discover seams (02): no Search-form-specific logic added to the Rust core.
- No live provider requests by the implementer (simulator screenshots stop before Search); device checks by the owner. PR left for owner review.

## Review Focus

1. Wi-Fi off mid-search: the search pauses within one request, unfinished route/dates are not marked failed, and Resume finishes them once online — Task 1.
2. Starting a search while offline is blocked with a clear message, and Resume stays disabled until the connection returns — Task 1.
3. Typing one letter ("a") in the picker stays responsive and still says how many more matches exist — Task 2.
4. VoiceOver can reach "Add major airports" as its own button, and a flight row reads price, stops, duration and warnings in one swipe — Task 3.
5. At the largest accessibility text size, flight rows and the detail screen do not truncate prices or overlap — Task 3.

### Design direction (frontend-design pass, owner request 2026-11-14)

**Subject and job:** a personal cheap one-way flight finder on the owner's iPad. The screen's
job is to answer two questions fast: *which day is cheapest* and *which flight is cheapest*,
with honest labels. Visual vocabulary comes from airfield signage (taxiway signs are yellow
with black lettering; gate/destination codes are wide, high-contrast letterforms), not from
generic travel-app cards.

**Colour (4 named tokens + system semantics):**

| Token | Value | Use (only) |
|---|---|---|
| Sign yellow | `#F5C400` | Fill of the primary action (Search) and the cheapest-day / cheapest-flight marker; text on it is always black |
| Sign black | `#000000` | Text on sign yellow (contrast ≈ 13:1, same in light and dark) |
| Hold red | `#D7262E` | Google stop states (rate-limited / blocked) only |
| Change orange | `#A64B00` light / `#FF9F0A` dark | Airport-change and stale-price warnings as text (system `.orange` fails 4.5:1 on white — found in the mockup) |
| Ground / ink | system `groupedBackground` / `label` / `secondaryLabel` | Everything else, so dark mode and Increase Contrast work for free |

**Type (one family, two widths, all Dynamic Type text styles):** SF Pro *Expanded* semibold
for IATA codes and the route header (signage feel, `.fontWidth(.expanded)`); SF Pro regular
for everything else; prices always tabular digits (`.monospacedDigit()`), so columns of fares
line up. No monospace face, no all-caps labels, no middle-dot strings — separate facts by
layout, not punctuation.

**Layout (iPad split view; left aligned throughout):**

```text
┌ Search ─────────────────┐┌ Results ─────────────────────────────────────────────┐
│  CGK  →  HND            ││  Mon  Tue  Wed  Thu  Fri  Sat  Sun  Mon  Tue  …        │  ← date ribbon:
│  (tap to change)        ││  1.92 1.48 ▇1.25 1.61  —  2.03 1.88  ···              │    lowest fare per day
│                         ││  15   16   17   18   19   20   21   22   23            │    (M IDR), cheapest in
│  15 Dec – 14 Jan        ││──────────────────────────────────────────────────────│    sign yellow; — failed,
│  Stops  Any|0|1|2       ││  IDR 1,250,000   CGK 21:45 → HND 07:00 +1   Nonstop  │    ··· still searching;
│  Currency IDR|USD|…     ││                  NH 856                     7h 15m   │    tap a day = filter
│                         ││  IDR 1,310,500   CGK 06:05 → HND 17:40      1 stop   │
│ ▐ Search 31 days ▌      ││                  GA 874 · SIN 1h 55m        10h 35m  │
│  (sign yellow, black)   ││  …                                                   │
└─────────────────────────┘└──────────────────────────────────────────────────────┘
```

- **Search side:** the route is a large code pair (`CGK → HND`, expanded, title size) that opens
  the picker; Major places show as the place name under the codes ("Tokyo, 2 airports").
  The action says what it does: "Search 31 days" (route/date count from the plan).
- **Results:** the **date ribbon** is the one bold element — a horizontally scrolling strip, one
  column per departure date with the lowest fare found that day; the cheapest day is a
  sign-yellow block with black text; days still pending show a quiet placeholder, failed days a
  dash with the reason on tap-and-hold. Tapping a day filters the list to that day (tap again
  for all). It fills in progressively as the search runs, which is also the progress display.
- **Flight rows:** price first (large, tabular), then the code-and-time line in expanded codes,
  then flight numbers and layovers small; stops and duration right-aligned. The cheapest flight
  carries a small sign-yellow "Cheapest" tag; everything else stays system-quiet.
- **Detail:** a vertical itinerary (it is a real sequence): departure, leg, layover or airport
  change, arrival — a thin rule connects the stops; the airport-change step is orange with
  plain words ("Change airports: ICN to GMP, 3h 20m" + "You must get yourself to the other
  airport and through security again. This is not a protected connection.").
- **Owner-approved mockup (2026-11-14):** [CheapWings iPad mockup](https://claude.ai/artifact/FVDZ95E1WazTXtPAqN1Rgb)
  — results light/dark, details, picker. Build to it.
- **Picker:** unchanged structure from P5.5; codes in the expanded width so tokens read like
  signs.

**Principles:** (1) spend boldness only on the date ribbon and the yellow marker; (2) codes look
like airport signs, everything else is plain system UI; (3) yellow always means "cheapest" or
"the main action", never decoration; (4) semantic system colours and text styles everywhere,
so dark mode, larger text and Increase Contrast need no special cases; (5) motion only in
answer to a tap (day filter, sheet), respecting Reduce Motion.

**Rejected while planning:** a split-flap departure-board animation (kitsch, constant motion,
hurts VoiceOver); a monospace face for codes (a generic data-label tell — expanded SF Pro gives
the signage look and keeps Dynamic Type); boarding-pass cards per flight (decoration that
costs vertical space in a list meant for scanning).
