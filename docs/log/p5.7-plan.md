# P5.7 — Move the web backend onto the shared Rust core

Approved implementation direction supplied by the owner, 2026-11-18.
Baseline: GitHub `main`, `bc4f5b2` (P5.4 merged), not the stale P4.13 checkout.
`WORK_LOG.md` owns compact status; [p5.7.md](p5.7.md) owns execution evidence.

## Design and boundaries

Migrate in reviewable checkpoints while preserving each platform's behavior.
Rust owns shared calculations and parsing. Python and Swift retain networking,
task execution and lifecycle; Python retains web storage, Swift calls the existing
Rust iPad store. Share pure scheduling policy with separate platform profiles.

REST/OpenAPI, React interfaces, database schemas, saved searches, environment
settings and default provider selections remain compatible. Extend existing
PyO3/UniFFI surfaces; no new service or transport framework, permanent dual
production implementations, or runtime migration flags. Host validation and
native errors remain. Exact decimal text and lossless source fields cross parser
boundaries. Shared code does not require identical platform policies.

One PR per checkpoint, owner-controlled merges. A checkpoint is ready only after
its parity/regression gates pass and `graphify update .` runs. Revert the checkpoint
for rollback. P6 release acceptance and P7 Discover remain separate. Live probes,
toolchain installations, production setting changes and merges require existing
owner approvals; none are implicit in this migration.

## Main risk and explicit exclusions

Behavior drift at parser/scheduler boundaries is the main migration risk.
Independent fixtures and separate platform profiles are release gates. Currency
policy fixes, swoop transport restoration, background continuation and deferred
product improvements remain separate. No database migration is planned.
