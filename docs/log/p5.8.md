## What exists now

| Area | Change |
|---|---|
| Pacing | The web's start-to-start logic on the iPad: a Fli request starts every 0.25 s with up to 6 open (`ProviderPacing.fli`). Replies are released in plan order, so checkpoints, the date strip and Resume see the same sequence as before; a slot frees when its reply is released. |
| Stops | 429, 401/403, refused redirect, traffic page, offline (incl. DNS/host errors) and cancel stop launching, cancel open requests and release nothing for the stopping route/date or later — those stay pending and Resume refetches them (no lost or duplicated day). |
| Provider seams (owner request) | `SearchProvider` protocol + `ProviderPacing` + `ProviderOutcome`; the generic `PacedRunner` has no Fli or Google knowledge; `FliSearchProvider` holds every Fli rule (moved unchanged). `SearchEngine(provider:)` composes them; the old `SearchEngine(transport:interval:maxInFlight:)` stays as a convenience. What P5.4 adds is written in the plan ("Plugging in more providers"). |
| Transport | `httpMaximumConnectionsPerHost` raised from iOS's default 4 to 6, so the cap is the engine's. |
| App | Uses `FliSearchProvider`; form says "… route/date searches, up to 6 at a time". |
| App icon (owner request) | Frontend-design pass, three concepts on the [design canvas](https://claude.ai/artifact/FVDZ95E1WazTXtPAqN1Rgb); owner chose **A, taxiway direction sign** (black arrow with wing-swept barbs on sign yellow). Light, dark (yellow on black) and tinted 1024 px icons in `Resources/Assets.xcassets`; SVG sources in `docs/design/app-icon/`. Also the Mac icon (Designed for iPad). |

## Rulings made during implementation

- `testStartsUpToMaxInFlightBeforeAnyReply` compares the set of started route/dates: with an
  instant test clock, concurrent requests reach the fake transport in any order.
- URLSession's default of 4 connections per host raised to the provider's 6.
- Existing tests pinned to `maxInFlight: 1` (sequential = the P5.6 engine) for determinism.
- After a stop, at most the requests already open (≤ 6) were sent; a reply that arrives during
  the 0.25 s pacing wait is seen at the next release, so one extra start can follow a 429 within
  that window — the same as the web.
