## Exact-date bridge (Skiplagged)

`sk_destinations_anywhere` probably returns a `dateRange` description, not a date.

Skiplagged also has `sk_flex_departure_calendar` [SK-rec]. For one route around a chosen date, it returns `points[].{departure, price, usdPrice}`. Its description says "the lowest one-way fares around a chosen departure, returning date → cheapest-price entries". That turns a destination lead into exact dated prices.

So discovery on Skiplagged would take two call kinds:
1. One anywhere call per origin per anchor date.
2. One flex-calendar call per shortlisted destination.

Both are bounded by the discovery call budget. The `select_discovery_plan` contract (Task 4) is unaffected: flex points become dated `DiscoveryObservation`s, and anywhere rows without a date are counted as undated.

The probe has to show whether `dateRange` holds a usable exact date, and how many days the flex calendar covers.

### `sk_destinations_anywhere`, one-way, IDR

| Origin | 2026-12-22 | 2027-01-26 |
| --- | --- | --- |
| CGK | **0 results** | 69 priced destinations (cheapest SIN US$55) |
| SUB | 42 (cheapest DPS US$46) | 44 (cheapest DPS US$53) |
| DPS | 26 (cheapest SUB US$46) | 24 (cheapest SUB US$53) |

- **Every row is priced** (205 rows). `dateRange` and `tripLength` are absent. Each `deepLink` is `/flights/{origin}/{dest}/{requested depart}`.
- **Each price is for the exact requested date.** Where the flex calendar has that day, it shows the same USD price (SUB–DPS 46 = 46, SUB–LBJ 110 = 110, DPS–SUB 46 = 46). Detailed search on that date found it too (below).
- **Prices are whole US dollars** (`usdAmount` is always an integer). `amount` is `usdAmount × pricing.rate`, a float in IDR. `pricing.rateAsOf` is given and `approximate: true`. There is **no price age** field.
- **Hidden city:** every row has `flightType: "Standard"`. There's no hidden-city row in this sample to show the other value.
- **Coverage:** the destinations are domestic Indonesia, Southeast Asia, Australia/NZ, Japan, India and more. CGK on 2026-12-22 returned nothing, while the same tool gave 69 rows for CGK on 2027-01-26. Whether that's a holiday-peak gap or flaky is unknown; one sample can't tell reproducibility.
- **Latency** 1.8–4.5 s, **size** 0.5–14 KB.

### `sk_flex_departure_calendar`

- It covers about ±30 days around the anchor date, clipped to tomorrow: 61 points for SUB–DPS, SUB–LBJ and DPS–SUB.
- **2 of 6 calls returned no points** (CGK–BKK, DPS–LBJ), and CGK–SIN returned 2 points without the anchor day. Detailed search still found fares on those routes.
- It can show a cheaper nearby day (SUB–DPS US$38 vs US$46 on the anchor). That's useful later, but not reliable enough for exact dates, which anywhere already gives.
- Latency 1.0–4.0 s.

## Go / no-go

**GO for Skiplagged `sk_destinations_anywhere` as the MVP discovery source** (owner sign-off required). Against the plan's criterion:
- Priced rows with exact departure dates for **3 of 3 origins** (CGK only in the second window).
- No auth, so it's reachable from the iPad through the existing MCP client.
- Terms: personal use, as accepted in P0.

What this means for Phase B:
- **The Task 4/5 contract holds unchanged.** Anywhere rows are dated (date = the requested `depart`), so the "undated" path is only a guard.
- **Discovery cost scales with dates, not destinations.** One call per origin per departure date returns every destination. A 7-day window from one origin is 7 calls. P7.4 needs a discovery call budget and should cap the window, or sample dates.
- **Adapter mapping (P7.4):**
  - `amount` = `usdAmount` as decimal text, `currency` = `USD`. CheapWings' own FX snapshot converts it; the server's approximate IDR `amount` is not used.
  - `departure_date` = the requested `depart`; `observed_at` = none; `fetched_at` = the call time; `price_kind` = `indicative`.
  - `hidden_city` = `no` when `flightType` is `Standard`, else `unknown` until a hidden-city value is seen.
  - `source_reference` = `deepLink` (utm stripped).
- **The flex calendar is optional, for a later "cheaper nearby date" feature.** It's not required for the MVP.

## Fli Explore addendum (owner-approved, 2026-11-21)

Upstream Fli commit `af5d0ed` ran in a throwaway virtualenv; the backend pin is unchanged. Tool: `scripts/provider_probe_fli_explore.py`. Fixture: `contracts/fixtures/provider/fli_explore_p71_20261121T073601Z.json`. It ran the same 6 origin/date points as Skiplagged, one-way to `ANYWHERE` in IDR, capped at 2 attempts per call and 60 s apart: **10 requests**.

| Origin | 2026-12-22 | 2027-01-26 |
| --- | --- | --- |
| CGK | refused (error 13 ×2) | refused (error 13 ×2) |
| SUB | refused (error 13 ×2) | 91 destinations, **67 priced**, cheapest SIN IDR 927,102 (Scoot nonstop) |
| DPS | refused (error 13 ×2) | 91 destinations, **68 priced**, cheapest SIN IDR 870,000 (Jetstar nonstop) |

- **Reliability is poor.** Google refused 8 of 10 requests with its transient error 13. Fli's own notes say about 40%. Fli's default 4 attempts might recover more, at the cost of extra traffic.
- **When it answers, the data is rich.** Every priced row is dated exactly the requested day. Prices come in IDR from Google, with airline, stops, duration and destination airport. About a quarter of the rows are unpriced places with no airport, which the adapter would drop.
- **Prices agree with Skiplagged where both list a destination**, within 0.5%:

  | Route | Fli | Skiplagged |
  | --- | --- | --- |
  | SUB–MEL | 9,999,613 | US$547 ≈ 10,006,216 |
  | SUB–PER | 8,683,800 | US$475 ≈ 8,689,128 |
  | DPS–PER | 5,122,005 | US$280 ≈ 5,122,012 |

- **Coverage barely overlaps (3 shared destinations per call), so the two are complementary.** Skiplagged returns Australia/NZ and domestic Indonesia (BNE, CNS, LBJ, …). Fli returns regional hubs and long-haul (SIN, CGK, BKK, HKG, Europe, US). Skiplagged's SUB list didn't include SIN, CGK or BKK at all.
- **The iPad needs new work.** Explore is a different Google endpoint from the search page the iPad's native Fli code uses, so it would need new Swift transport and parsing.

**Updated recommendation:**
- **Skiplagged anywhere is the primary discovery source on both platforms:** reliable in this sample and no extra iPad transport.
- **Fli Explore is a second, opportunistic discovery source.** Its leads widen coverage when Google answers. A refusal is recorded as a provider outcome and never as "no destinations". It isn't counted on for the iPad until a Swift transport exists.
- The shared Rust contract already takes observations from several sources, so adding Fli is adapter work only. Bumping the backend Fli pin to include Explore is a separate owner decision.

**Owner decision (2026-11-21): GO.** Skiplagged anywhere is primary on both platforms; Fli Explore is an opportunistic second source, web first. Phase B (P7.2 contract) may start.
