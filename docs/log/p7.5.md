# P7.5: Discover on web

Plan: [p7.5-p7.6-plan](p7.5-p7.6-plan.md) Tasks 1–4. Runtime: [P7.4](p7.4.md). Stacked on #29.

## What exists now
- **Header:** a `Search | Discover` toggle. Search is unchanged. Discover has its own job id in the URL (`?discover=<id>`), so a reload restores it.
- **Discover form:**
  - Origins through the existing airport picker, departure window, optional budget, display currency.
  - It shows which sources discover and which check.
  - A live counter shows "N discovery calls (max 31)". Submit is disabled over the limit.
- **Discover view:**
  - A status strip with discovery calls, destinations found and checks.
  - The backend's coverage line, "Lowest fares found among N discovered destinations; M checked."
  - Failed and unpriced call counts, and sources that stopped us.
  - A separate message for each outcome: unavailable, no prices, none under budget, timed out.
  - **Destination rows:** each shows a "Discovery price (provisional)", a checked fare once one exists, and its state (checking or no checked fare). Checked fares rank first, by checked price.
  - The checked itineraries reuse the existing results workspace and sort bar.
- **Backend:** `DiscoveryStatus.shortlist` (origin, destination, date, comparable amount in the display currency), stored at planning time.
- **Logic:** `src/lib/discover.ts` (`discoveryCallCount`, `outcomeMessage`, `compareDecimal`, `discoverRows`) does the row building and exact decimal ordering, with no floats.

## Limitations
- Checked results are fetched as one page of up to 100 itineraries, with no load-more.
- No region or country filters, and no Surprise Me.
- Only a synthetic API was used. No live providers.

## Final review (P7.5 + P7.6)
A fresh reviewer read both PRs. It found no Critical issues and two Important ones on web, both fixed test-first:
- **Rows could say "No checked fare" for a checked destination** whose fares were beyond the first results page. Each shortlisted route/date now carries `checked_amount` and `checked_itinerary_id`, computed on the server from every stored quote. The rows use them.
- **The mode toggle cleared the job being viewed.** Each mode now keeps its own job, and switching only changes which one is shown.
