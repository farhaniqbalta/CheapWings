# P7.6: Discover on iPad

Plan: [p7.5-p7.6-plan](p7.5-p7.6-plan.md) Tasks 5–7. Runtime: [P7.4](p7.4.md) PR B. Stacked on #30.

## What exists now
- **Form:** a `Search | Discover` segmented picker at the top of the form. Search is unchanged.
- **Discover inputs:**
  - The From airports only, using the existing picker with Major support.
  - Departure dates, stops, currency, and an optional budget (decimal keypad).
  - The selected sources check the fares; Skiplagged finds the destinations.
  - The footnote shows "N discovery calls to Skiplagged (max 31), then fares checked on …", or the core's reason (for example `too_many`) before any request.
- **Engine:** `SearchModel` builds the session with `SkiplaggedDiscoveryProvider()`. A restored Discover run brings back the Discover mode and budget.
- **Discover results** (the detail column follows the run being shown):
  - **Status:** unfinished-run Resume, sources that stopped us, progress ("Finding destinations: x of y calls", then "Checking fares: x of y checks"), the coverage line "Lowest fares found among N discovered destinations; M checked", and failed and unpriced call counts.
  - **Outcomes:** source unavailable, no prices, none under budget.
  - **Destination rows:** each has the code, place name, origin, date, *Checked fare* (tap for the existing offer details) or "Checking…" / "No checked fare", and *Discovery price (provisional)*. Checked fares come first.
- **CheapWingsKit:**
  - `DiscoverySummary.selected` is the shortlist, set at commit and recomputed on restore.
  - `discoverRows(summary:offers:currency:finished:)` builds and orders the rows (exact `Decimal` comparison).

## Limitations
- The SwiftUI screens are checked by build and Kit logic tests only. There's no UI automation, and the owner check on a device is pending.
- No region filters and no Surprise Me. Discovery makes one call at a time (from P7.4).
- No live Skiplagged call has been made from the iPad yet. P7.7 acceptance needs owner approval.
