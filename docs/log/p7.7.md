## Live web run (owner-approved, 2026-11-27)
**Setup:** the P6 pattern.
- A disposable SQLite database, migrated with `alembic upgrade head`.
- Loopback Uvicorn (`cheapwings.main:app`) plus a separate `cheapwings.worker`.
- `ENABLED_PROVIDERS=skiplagged,fli`, `MAX_WORK_ATTEMPTS=1`.
- `MAX_ROUTE_DATE_COMBINATIONS=20`, which caps the shortlist and so caps live checks at 40.

**Request:** `POST /api/v1/discover` for CGK, 2027-01-26 to 2027-01-28, IDR, checked by Skiplagged and Fli. It started at 05:35 UTC and took 375 s end to end.

## Verdict
- **Discovery: accepted live.** Skiplagged anywhere returned exact-date priced destinations through the shared parser. Selection, the cap, the single planning transaction and honest coverage all held.
- **Checks: limited upstream, not by Discover logic.**
  - Skiplagged rate-limited the checks that followed straight after discovery, even at its 3 s pacing.
  - Fli could not open TLS connections to Google on this run. The same transport serves Search, and this is related to the open P6 web Fli transport item.
- **The screen's honesty mostly held.** One gap: rows whose checks *failed* say "No checked fare", and the status strip doesn't state the failed-check count. This is a deferred P7.5 minor, now evidenced live.

## Follow-ups (proposed)
1. **Discover UI:** show failed checks. Add a failed-check count to the strip and a "Check failed" state per row on web and iPad.
2. **Skiplagged checks after discovery:** slower pacing for Skiplagged checks in a Discover run, or rely on the default 3 attempts. The 429 waits (~60 s) are retryable.
3. **Fli `curl_code=35` and `invalid_currency` on long-haul routes:** investigate with the existing Search path. This also affects Search.
4. **The deferred minors** from P7.4–P7.6, including purging discovery observations with expired fare data (provider retention).

The disposable database and server logs were left in the session scratchpad and are not committed.
