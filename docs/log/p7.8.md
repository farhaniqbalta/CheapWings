# P7.8: fixes from the P7.7 live run

The owner chose to fix first, with normal retries and nothing slowed down (2026-11-27). Branch `p7.8-fixes` → `p7-implementation`.

## 1. Failed checks are shown (live run: 38 of 40 checks failed and rows said only "No checked fare")
- **Backend:** each shortlist entry carries `check_status`: `checked`, `pending`, `no_fare`, `failed` or `not_checked`. The status adds the warning "N checks failed (source errors or limits); those destinations show a discovery price only."
- **Web:** a "Check failed" row state and a FAILED count in the status strip. The counts wrap at phone width.
- **iPad:** `failedRouteDates(planned:finished:failures:)` drives a "Check failed" row state and a failed-check line in the coverage section.

## 2. Skiplagged checks after discovery: normal retries, no extra pacing
No code change. The live run used `MAX_WORK_ATTEMPTS=1`, so the ~60 s 429 waits became final. The defaults already retry:
- web allows 3 attempts and waits out the Retry-After;
- the iPad's `PacedRunner` allows up to 3 attempts.

`test_rate_limited_check_is_retried_normally` pins this for Discover checks.

## 3. Fli
- **`invalid_currency`:** one offer in a currency other than the display currency used to fail the whole route, losing its IDR fares. Those offers are now dropped and counted as unpriced. A page with **no** display-currency offer still fails with `invalid_currency`, so an all-foreign page never looks like "no fares". This also applies to Search, matching the iPad's per-offer handling. The `mixed_currency` case left the parity reference (`test_p78_fli_currency.py`).
- **`curl_code=35`:** a TLS connect failure, mapped to `provider_unavailable`, which normal retries already cover. Its root cause could not be found offline. It needs a live diagnosis, which requires owner approval.

## 4. Deferred minors closed
- **Retention:** discovery observations and the shortlist prices are purged when their fare data expires. Coverage counts stay.
- **Endpoints:** `GET /searches/{id}/results` returns 404 for a Discover id.
- **FX:** web planning uses the last non-empty FX rate, as the iPad does.
- **Web Discover screen:**
  - one failed-calls line;
  - errors are kept per job;
  - a Discover start that finishes after a switch to Search doesn't pull the view back;
  - "loading sources…" while capabilities load.
- **iPad:**
  - the budget accepts "1.500.000", "Rp 1 500 000" and "250,50" (`BudgetText`);
  - Discover keeps "Major airports" origins across a relaunch.

**Still deferred:**
- `strip_utm` is case-sensitive. This is cosmetic, and fixing it means a core change.
- `startDiscover` swallows its error, which is already validated beforehand.
